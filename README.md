# In-Memory Workload Engine

Primitive `int` implementations of a dynamic array, a singly linked list and an array-based min-heap. The project compares indexed access, search, boundary and middle updates, and priority processing using operation counters and reproducible workloads.

## Requirements

- JDK 17 or newer
- Maven 3.8 or newer

Run commands from the project root. Maven downloads JUnit and build plugins on the first build. The application has no external runtime dependencies.

## Build and test

```sh
mvn clean verify
```

JUnit 5 tests cover randomized comparisons with reference collections, empty and singleton structures, duplicates, extreme integers, index validation, resizing, exact counters, and the heap property after each mutation.

## Run the benchmark

One command builds the project, runs the tests, measures all workloads and generates the CSV and PNG charts:

```sh
mvn verify -Pbenchmark
```

After compilation, the benchmark can also be run directly, with an optional output directory:

```sh
java -Djava.awt.headless=true -cp target/classes kz.aitu.daa.Benchmark
java -Djava.awt.headless=true -cp target/classes kz.aitu.daa.Benchmark results
```

The output is `results/results.csv` (36 cases) and `results/plots/W1.png` through `W4.png`. Each chart has time, steps, moves and comparisons panels. Time and input size use logarithmic axes; counters use `log10(1 + count)` so zero remains visible. Coincident series may overlap.

## Data structures

| Structure | Operations | Storage |
| --- | --- | --- |
| `DynamicArray` | `add(value)`, `add(index, value)`, `remove(index)`, `get(index)`, `contains(value)` | `int[]`, initial capacity 8, doubles when full |
| `MyLinkedList` | Same five methods through `IntList` | Nodes with an `int`, a next link, and head/tail references |
| `MinHeap` | `insert(value)`, `peekMin()`, `extractMin()` | `int[]`, initial capacity 8, doubles when full |

All structures expose `size()` and `metrics()`. Removal returns the removed value. Lists accept insertion indices from 0 through size; other indexed operations require 0 through size - 1. Invalid indices throw `IndexOutOfBoundsException`. Empty heap access throws `IllegalStateException`. Arrays retain capacity after removal.

## Workloads

Each workload uses sizes 100, 1,000, 10,000 and 100,000. Input values are generated by `new Random(42)` as non-negative even integers. Both list implementations receive identical values in identical order and identical query sequences.

| Workload | Measured operations |
| --- | --- |
| W1 | 10,000 random `get(index)` calls |
| W2 | 1,000 searches: 500 sampled present values and 500 negative values guaranteed absent |
| W3 head | 1,000 insertions at index 0, followed by 1,000 removals at index 0 |
| W3 middle | 1,000 insertions at the original index `n / 2`, followed by 1,000 removals at that same index |
| W4 | Insert all n values into an empty heap, then extract all n minima |

The JVM first runs 100 discarded rounds of all cases at n = 1,000. Each measured case then gets five discarded warm-up runs and five recorded runs using fresh structures. `time_ms` is the median of the five complete workload times. Counters must agree across recorded runs. Times vary with the machine and JVM; operation counts are deterministic.

For W1-W3, filling, generating queries, allocating output buffers, validation and chart generation are outside the timed region. Counters reset after filling. W3 includes any resizing caused by its insertions. W4 includes insertion and extraction, including resizing, but validates sorted output after timing. Checksums are consumed through a volatile field. Measurements include counter overhead and are intended for workload comparison rather than isolated instruction timing.

## Counter definitions

Counters are incremented inside structure methods and stored as `long`.

- **steps**: one backing-array cell read, or one evaluation of a node's next link while following the list (including a transition to null). Reading a node's `int` value is not an array read or link traversal.
- **moves**: one relocation of an existing array element, including a resize copy; one persistent link assignment in the list, including head and tail; or one heap element relocated. A heap swap counts as two moves. The initial array write of a newly inserted value is not a relocation.
- **comparisons**: one comparison between element values. Bounds checks, loop conditions, index calculations and null checks are excluded.

For example, array `get(i)` takes one step; list `get(i)` follows i next links. List head insertion counts two link updates and head removal counts one (two when removing its only node). Local cursor assignments and implicit object initialization do not count as link updates.
